# Report Function Guide

## Purpose
Generates a PDF from a portfolio snapshot. It is stateless: portfolio-service owns report status and storage. The function can run as a normal container in Compose and through OpenFaaS in Kubernetes.

## Planned module files

| Path (under `backend/report-function/`) | Responsibility |
|---|---|
| `build.gradle.kts` | Spring Cloud Function Web, PDF library, validation, and unit tests. |
| `ReportFunctionApplication.java` | Spring Boot function application entry point. |
| `function/ReportGenerator.java` | Exposes the `Function<ReportRequest, byte[]>` bean expected by Spring Cloud Function. |
| `domain/ReportRequest.java` | Input snapshot contract: report ID, generated-at time, cash, holdings, and P&L. |
| `domain/ReportDocument.java` | Internal immutable values prepared for rendering. |
| `render/PdfReportRenderer.java` | Renders title, account summary, holdings table, and timestamp into PDF bytes. |
| `render/` supporting classes | Fonts/layout helpers; keep rendering separate from HTTP and portfolio persistence. |
| `resources/application.yml` | Function routing, payload limits, and server settings; no credentials. |
| `src/test/...` | Validates request handling and checks generated bytes/content type and key report fields. |
| `Dockerfile` | Packages the same function artifact for local container and OpenFaaS wrapper. |
| `deploy/openfaas.yml` (or deployment stack entry) | Declares image, gateway route, and scale bounds for OpenFaaS. |

The function returns PDF bytes and does not write to a database, Redis, or shared file system. See [ADR-0003](../../architecture/adr/0003-faas-spring-cloud-function.md).
